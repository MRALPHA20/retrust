Quick start

  1. Install and build the database. Python 3.10+ is the only requirement. About 165 MB and two minutes. 
    $ git clone https://github.com/<you>/retrust.git && cd retrust
$ python3 -m retrust.cli setup
  2. Find the product. Advisories spell names their own way, so start by looking yours up. 
    $ retrust search "S7-1500"
  3. Score it, or compare a shortlist. Add --html decision.html for a report to attach to the requisition. 
    $ retrust score --order-number 6ES7518-4AX00-1AB0 --version 3.1.6
$ retrust compare --candidate "ABB|AC 800M" --candidate "Moxa|EDS-405A"

Would rather be asked than type flags? retrust shell gives you a menu covering everything here, prints the equivalent command each time, and saves the result as HTML, JSON or CSV when you are done. Prefer a browser? retrust serve puts search, scoring, comparison, alternatives and vendor profiles on 127.0.0.1:8765, local to your machine and read-only.

1   What it is for

ReTrust helps a procurement team review named OT candidates before deployment, using the public security evidence available for each option.

It reads public advisory data, keys on the manufacturer order number a purchase requisition already contains, and shows the evidence behind every number it prints. It runs entirely offline against a local database, so a result is reproducible and a demonstration never depends on the network.

2   How it works

The four-rung resolution ladder

A buyer asks about "Siemens SIMATIC S7-1500, firmware 3.1.6". ReTrust decides which advisory products that refers to, strongest strategy first, and reports which rung answered.

RungMethodConfidenceSource-advisory recovery
1Manufacturer order number0.98100%
2Vendor + product name0.9099.8%
3Vendor + all query words present0.70100%
4Abstain, with a typed reason——

A wrong answer about whether a PLC is vulnerable costs more than "needs review", so abstention is a feature rather than a failure.

Scoring pillars

PillarExponentWhat it reads
Exposure0.60per-finding risk (threat × reachability × impact × applicability), concentrated on the worst few
Patch availability0.20a fix, a workaround, or nothing
Vendor practice0.15own CSAF feed, and advisory completeness
Certification0.05IEC 62443 (ISASecure) and Common Criteria

The weighted result is reported as a band: PREFER at 70 or above, CONDITIONAL at 40 or above, AVOID below. If network exposure is not supplied, that pillar is omitted and the five evidence weights are normalized to 100%. Weights and thresholds are yours to change — run retrust config --init.

Reported, but deliberately not scored Evidence confidence. The share of findings whose version range parsed cleanly and which carry CVSS and EPSS data. Folding it into the score would mean "we have good data about how bad this is" raises the score, which is backwards. It tells you how far to trust the verdict, not how safe the product is.

3   Installing and running it

ReTrust needs Python 3.10 or newer and nothing else. There are no third-party packages, so there is nothing to resolve, nothing to pin, and no virtual environment to create.

Two commands, from nothing to a working tool

$ git clone https://github.com/<you>/retrust.git && cd retrust
$ python3 -m retrust.cli setup

setup fetches CISA's OT advisory corpus, the KEV and EPSS exploitation feeds, and the certification and sanctions lists, then builds the local database. That is about 165 MB and a couple of minutes on a normal connection.

  [1/4] CISA OT advisories (~148 MB) ...
        3,938 advisory files
  [2/4] CISA Known Exploited Vulnerabilities ...
        1.8 MB
  [3/4] FIRST EPSS scores ...
        11.5 MB
  [4/4] Build the local index ...
        3,937 advisories, 28,951 products, KEV 1,726, EPSS 12,031

Ready.

If it is interrupted, run it again. Each step is skipped when its output is already there, so a dropped connection costs you only the step it dropped on. Downloads go to a temporary file and move into place once complete, so a half-fetched feed is never mistaken for a whole one.

FlagEffect
--offlineBuild from data already downloaded; fetch nothing
--forceRe-fetch sources even if they are present
--skip-refreshSkip the certification and sanctions lists
--data DIRKeep the data somewhere other than data/
It refuses to finish on an incomplete database If KEV or EPSS is missing, the exploitation gate cannot fire, and a product with a known exploited vulnerability would score as merely mediocre. Setup stops and says so rather than handing you a plausible-looking result.

Getting the retrust command on your PATH

Optional. Everything above runs straight from the clone. To type retrust instead of python3 -m retrust.cli:

$ python3 -m venv .venv && source .venv/bin/activate
$ pip install -e .

The virtual environment is not optional on Debian, Ubuntu or Kali: those ship Python as an externally managed environment, and pip install -e . outside one fails with a PEP 668 error. Both forms are equivalent throughout this guide.

Two things make it more than a wrapper. Every choice prints the command line it is equivalent to before it runs, so anyone using the menu graduates to scripting without being taught. The candidate string is pipe-separated: Vendor|Product|Version|OrderNumber, and everything after the vendor is optional.

In the browser, Compare candidates provides separate fields for an order number, vendor, model and optional firmware. An exact order-number search keeps that identifier when you open its assessment and compare it. Download the whole shortlist as HTML, JSON or CSV. Reading the result

ColumnWhat it means
VERDICTPREFER ≥70, CONDITIONAL ≥40, AVOID below, NOT ASSESSED when it could not resolve the product
SCOREThe weighted composite, 0–100, higher is better
CVESDistinct CVEs in scope. Raw total volume is not a scoring penalty
ROBUSTThe share of sampled weightings supporting the most common verdict; not ranking stability
NOTESThe gate that decided it, if one did
ROBUST is the column most worth reading The usual objection to any composite score is that its weights were invented. ReTrust measures that rather than arguing about it: it samples hundreds of weightings from across the whole simplex and reports how often the verdict survives. A verdict holding under 91% of weightings is a result. One holding under 77% is a judgement call, and the tool says so instead of handing you a false precision.

5   The rules that keep it honest

  • Raw CVE counts are never scored. A vendor that discloses diligently would rank below one that stays quiet — exactly backwards.
  • A product it cannot resolve gets no score at all. Every pillar reads "no CVEs found" as good news, so an unresolvable product would otherwise score near 100 and top the comparison. NOT ASSESSED sorts below AVOID.
  • Missing certification is never a penalty. Most OT products are never submitted, so absence says nothing. A certificate can only add.
  • Unparseable version ranges stay in scope and are flagged, never assumed safe.
  • Sanctions screening never fuzzy-matches. Wrongly flagging a real manufacturer is the worst error this tool could make, so it matches exact identity-preserving names only.
  • No advisories is not evidence of safety. It may simply mean nobody has published.

ReTrust redistributes no vendor data. It reads these at build time and cites each one in every report footer, so a result stays interpretable months later. Screening and certification results are reproductions of what those sources publish: decision support for a buyer, not a legal determination. Verify any gate against the cited source before acting on it.
