ReTrust

Security evidence before the purchase order

ReTrust helps you review industrial equipment before buying it. Give it a manufacturer order number or vendor and model, then confirm the deployment and firmware with your technical team.

What problem does it solve?

Public vulnerability notices, fix information and supplier restrictions are spread across sources. ReTrust brings those records into one assessment and preserves the reasons behind it. It supports procurement decisions; it does not prove a product is secure or suitable for a process.

How to use it

  1. Identify the product. Enter the exact order number or vendor and model. Add the planned firmware when known.
  2. Establish access. Network context and actual reachability are main inputs. Isolation alone does not prove an attack path is blocked.
  3. Check consequences and fixes. Ask an engineer what each weakness could do to the process, and whether the selected firmware is affected or patched.
  4. Read the outcome. Blockers override the number. Missing material information produces VERIFY and a provisional range.
  5. Save the evidence. Export HTML or JSON, ask the supplier specific questions, and reassess when evidence changes.

Understand the outcomes

PREFER
70 or higher, with material inputs resolved and no blocker. Confirm suitability before approval.
CONDITIONAL
40 to below 70. Review the stated risks and commitments.
AVOID
A mandatory blocker or a score below 40 makes this unfavourable.
VERIFY
Technical checks are still needed. The range shows how the score can change.
NOT ASSESSED
Insufficient product evidence to calculate a score.

What is behind the number?

Exposure safety carries 60%, available fixes 20%, vendor practices 15% and certification evidence 5% in a weighted product. Exposure uses threat evidence, actual attack access, credible OT harm and affected firmware status.

RT4 uses Z=T×A×H×U, R=min(1,Z1+.20Z2+.10Z3) and E=100(1−R). A contribution of .48 gives E=52; adding .20 and .10 gives E=47. Higher scores are more favourable, not percentages of safety.

Duplicate advisories for one CVE count once. Different CVEs are review units, not proof of independent attack paths. The tool does not build a verified attack graph.

Three interfaces, the same evidence

  • Browser: run retrust serve and use the main assessment form.
  • Menu: run retrust shell for guided terminal actions.
  • Commands: use retrust score, compare or batch for repeatable checks and exports.

See the command reference.

What it cannot verify for you

ReTrust reads public evidence and operator statements. It does not scan your plant, independently verify a firewall rule, test firmware binaries or establish functional equivalence between products. Site-wide answers must be justified for all findings in scope.

The proposed weights and OT consequence values require validation. Historical benchmarks from earlier models do not establish RT4 procurement accuracy.
