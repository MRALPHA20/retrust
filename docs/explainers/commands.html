The command reference

Every ReTrust command, by the job it does.

ReTrust is one program — retrust — with a verb after it. You rarely need more than four. The rest are here for when a question comes up.

Start here

The whole day-one workflow is four commands (plus a one-time setup).

  1. setup— once: fetch the public sources and build your local index.
  2. search moxa— find the exact product (shorthand and re-ordered words are fine; spell the name right).
  3. score …— assess one product: verdict, pillars, evidence.
  4. compare …— put a shortlist on equal terms and rank it.

Not on the command line? retrust serve opens the same thing as a browser workspace, and retrust shell is a menu that asks questions instead of taking flags.

01

Find & assess

The core loop: name a product, get a verdict.

search

Find a vendor, product or order number in the index.

Use it first, when you don’t know the exact model. Shorthand and re-ordered words still land — --vendor ABB --product "800M AC" reaches AC 800M, because every word of what you typed appears in the name. A misspelling does not: retrust search Siemems prints No product in the corpus matches 'Siemems' and exits 1, and score --vendor Siemems … returns NOT ASSESSED with no shortlist. That is deliberate — guessing which manufacturer you meant would put a report under the wrong company's advisories, so ReTrust abstains and retrust eval counts the abstention as a pass. Only retrust vendor Siemems offers near-name suggestions (Siemens, similar 0.86); for a product, reach for the order number instead.

retrust search "simatic s7-1500"

score

Assess one product — the verdict, the four pillars, and the evidence behind each.

Your main command. Add --version to narrow it to the firmware you’d actually buy.

retrust score --order-number 6ES7518-4AX00-1AB0 --version 3.1.6

Four answers narrow the range, and each one can only narrow it: --consequence (what a compromise costs this process), --interface (have you verified the vulnerable interface is unreachable), --prerequisites (can an attacker meet the privileges, interaction and conditions the CVSS vector demands) and --remediation (is the fix actually on the box). --assessment-type says whether this is a purchase or an installed asset. Leave any out and it stays unresolved rather than guessed — ABB AC 800M bare is VERIFY 68.0–87.7; --consequence control lifts the floor to 72.2, and --interface blocked collapses the range to a single 87.7.

--prerequisites is the one that settles reachability for every attack vector. --interface exposed answers a network question, so on its own it resolves only a remotely-reachable flaw; a local or physical flaw also needs execution on the box or hands on the cabinet, and the network answer says nothing about either. Without that distinction an AV:P flaw would score exactly like an unauthenticated remote one.

--network-exposure is recorded as context and never scored: topology is not a reachability discount, so isolated, it_ot and internet_ot all return the same 68.0–87.7 on that product. It is still worth declaring — it goes into the assessment vector and the record — but an unanswered one leaves a verification item rather than moving the number.

compare

Rank several candidates for one decision, on equal terms.

When you have a shortlist and need to say which one goes on the purchase order.

retrust compare --candidate "ABB|AC 800M" --candidate "Moxa|EDS-405A"

shell

An interactive menu — no flags to remember; it prints the equivalent command each time.

For a first look, or for colleagues who don’t live in a terminal.

retrust shell

serve

The same assessments as web pages on 127.0.0.1.

For whoever signs the order — search, assess, compare and download evidence in a browser.

retrust serve # then open http://127.0.0.1:8765

02

Dig into the evidence

Follow a verdict back to where it came from.

vendor

Everything the index holds on one manufacturer — advisories, screening and certification status.

When you’re weighing a supplier, not just a single part.

retrust vendor "Schneider Electric"

alternatives

Other products in the same vendor family, scored the same way.

When a candidate scores poorly and you want safer options to put to an engineer.

retrust alternatives --vendor Moxa --product EDS-405A

cve

One CVE, and everything the index knows about it — which products it touches, KEV, EPSS.

When a specific vulnerability lands in the news and you need to know your exposure.

retrust cve CVE-2023-44487

timeline

A vendor’s (or product’s) advisory history drawn as a shape: cadence, fix share, quiet time.

To see whether a supplier discloses steadily or has gone suspiciously quiet.

retrust timeline --vendor Siemens

questions

An RFQ security annex — the questions the evidence supports, ready to paste into a request for quotation.

When you’re about to go back to the supplier and want to ask the right things.

retrust questions --vendor Moxa --product EDS-405A

03

Decide & prioritise

Turn evidence into a response, and test how firm the verdict is.

ssvc

Place each finding on CERT/CC’s SSVC decision tree to get a response priority.

When you already own the product and need to decide how urgently to act.

retrust ssvc --vendor ABB --product "AC 800M"

lev

How likely a finding has already been exploited, from the EPSS history (NIST CSWP 41).

A prompt to go and look — a lower bound from a model, never a claim it happened.

retrust lev --vendor Siemens --product "SIMATIC S7-1500"

sensitivity

Re-runs the verdict under many random weightings and reports whether it holds.

To know if a verdict is solid or a “judgement call” that depends on the exact weights.

retrust sensitivity --vendor ABB --product "AC 800M"

config

Show or create the scoring weights; --appetites lists the shipped risk profiles.

When your organisation weighs risk differently and you want to adjust — transparently.

retrust config --appetites

04

Supply chain & pipelines

Score many things at once, and fit into automated checks.

batch

Score a whole bill-of-materials or a CycloneDX SBOM — with a CI exit code.

For a full equipment list, or a build pipeline that should fail on a gated part.

retrust batch components.csv --json out.json

vex

Write one product's assessment as a CycloneDX VEX document: a product query in, one statement per CVE out.

When a customer or regulator asks for machine-readable exploitability statements. It takes the same identity flags as score — not an SBOM path; feed an SBOM to batch, which reads CycloneDX. Statements cover only the CVEs this index's advisories name for the matched rows: a CVE absent here was never assessed, which is a different fact from not affected.

retrust vex --vendor Moxa --product EDS-405A --out vex.json

diff

Re-score a stored result and show what changed since you saved it.

To see whether a product got better or worse between two reviews.

retrust diff saved-assessment.json

05

Trust the data

Prove the inputs are genuine and the numbers reproduce.

verify

Are the advisories the ones CISA published? Checks SHA-512 digests and PGP signatures.

Before trusting a result. Add --strict so a pipeline fails unless origin is positively established.

retrust verify --strict

doctor

Is this installation current enough to trust right now? Flags stale feeds and says what to run.

Any time before a decision — KEV and EPSS age, and a stale feed changes verdicts.

retrust doctor

eval

Reproduce the published accuracy figures from your own index.

When someone asks “how do you know the matching is right?” — they can re-run it.

retrust eval --sample 4000

backtest

Did the score predict later disclosure? --sweep tries five cutoffs.

For the honest limits of the method — a diagnostic, not a promise of prediction.

retrust backtest --sweep

stats

Plain counts from the index: advisories, products, vendors, CVEs, KEV entries.

A quick “what’s loaded?” check.

retrust stats

06

Manage the data

Build, extend, refresh and pin the local index.

setup

The all-in-one: fetch every source and build the index. Run once to get started.

First install, or a full rebuild. Needs network; everything after runs offline.

retrust setup

ingest

Build the index from one or several CSAF advisory directories you already have.

When you manage the source files yourself instead of letting setup fetch them.

retrust ingest --csaf data/CSAF

provider

Fetch a vendor’s own CSAF feed and index it beside the CISA corpus.

To add a manufacturer’s first-party advisories (e.g. Siemens) for deeper coverage.

retrust provider https://…/provider-metadata.json

refresh

Update the certification and sanctions / covered lists.

Periodically — screening lists change whenever a government acts.

retrust refresh

snapshot

Pin all the data into one portable, checksummed file.

For a reproducible record (“this is the data that produced this verdict”) or an offline demo.

retrust snapshot --note "Q4 procurement review"

07

Extras

Nice-to-haves you’ll reach for occasionally.

screenshot

Render an HTML report to a PNG image.

For a slide or a document, when a picture of the report is easier to share than the file. The flag names a directory, not a file. Write --out-dir in full: argparse accepts --out as an abbreviation of it, so --out report.png succeeds and quietly creates a folder called report.png with the image inside.

retrust screenshot report.html --out-dir shots/

completion

Print a shell tab-completion script for bash or zsh.

One-time convenience so the shell completes commands and flags for you.

retrust completion zsh

demo

Run the whole workflow end to end.

To show the tool off, or to sanity-check a fresh install in one go.

retrust demo

Lost? Run retrust on its own — it prints what the index holds and what to try next. Every command also takes --help.
